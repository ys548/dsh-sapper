## 📁 报告目录结构（强制）

```
reports/【目标】/
├── 总报告-<目标>.md            ← 本文件（顶层，唯一交付入口）
├── 攻击面快照.md              ← 攻击面快照（顶层）
├── platform-report.md          ← 平台导出（可选，顶层）
├── 漏洞报告/                   ← 每漏洞一个子文件夹（单漏洞报告 + 该漏洞专属证据）
│   ├── 01-<短名>/<报告标题>.md + evidence/   ← ⛔ 报告不叫"漏洞报告.md"，以标题命名
│   ├── 02-<短名>/<报告标题>.md + evidence/
│   └── ...（序号 = 确认顺序）
├── 专项报告/                   ← 过程性专项报告（recon-*.md / exploit-*.md）
└── raw/                        ← 原始数据/中间产物/缓存/脚本/JS样本（按阶段分子目录，含 README.md 映射）
```

> 总报告位于 `reports/【目标】/` 顶层；每个漏洞的详细内容与证据在其对应文件夹 `漏洞报告/XX-<名称>/` 中，总报告"漏洞详情"章节只贴摘要并引用对应文件夹路径。
>
> **顶层白名单**：顶层只允许 `总报告`、`攻击面快照`、`平台导出` 三个报告文件 + `漏洞报告/`、`专项报告/`、`raw/` 三个子目录；其余 json/txt/csv/py/html/png 等中间产物一律进 `raw/<阶段>/`，禁止散落顶层。
