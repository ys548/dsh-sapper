# 评分与定级口径

> 这份口径来自甲方（验证机构）的评分标准，是**定级与「值不值得报」的唯一裁判依据**。报告格式按 `report-00-report` 的模板；**定级、是否收，一律按本文**。两者冲突时以本文为准。若项目方下发了自己的标准，以项目方标准替换本文对应条目，其余照用。

## 1. 单条评分

| 等级 | 积分 |
|---|---|
| 高危 | 100 |
| 中危 | 40 |
| 低危 | 10 |

以验证机构最终评定为准，不是自己说了算。

## 2. 加分项

- **未报备新增资产**：每个 +100，须证明归属（备案信息、招标文件、负责人确认等）。
- **严重敏感个人信息泄露**：按条数分段加分 —— [100, 1000) +50；[1000, 1 万) +100；[1 万, 10 万) +200；[10 万, 100 万) +300；100 万以上 +500。**不同系统相同数据只算一次**。
- **入侵痕迹溯源**：历史 webshell 仍可连 +100；完整溯源过程 +100。
- **安全事件**：网页篡改 / 挂马 / 暗链，各按 100 分。

## 3. 资产范围

- 只收**下发资产**的漏洞。新增资产必须先上报入库、再测试（入库后全员通知）。
- 禁止横向打内网（除非授权明确含内网）。
- 匹配规则：纯 IP / 域名 = 该主机全端口；`IP:端口` = 仅该端口；网站 URL = 该域名下全端口。

## 4. 重复与合并

- 同平台同模块同类型：只对最早 2 个打分。
- 同平台不同模块同类型：只对最早 3 个打分。
- 相同单位不同系统、同框架同漏洞：只对前 3 个打分。
- 跨机构重复：只给最早。
- 同队重复提交 = 违规。
- **前后关联漏洞合并处理**（例如弱口令进后台后的注入或越权并入该弱口令报告），是否准许继续深入由审核员评估。

## 5. 平台不收清单（可以注明，但不计分）

版本信息、IP 端口等资产信息泄露；后台 / 数据库 / SSH 可访问但需账密；未自定义错误页；无敏感信息的配置泄露；明文传输；DoS；SPF 配置不当；测试者自有信息泄露；跨域访问未超过用户权限的数据（CORS 无权限增量）；SQL 注入仅报错无数据；HOST 头攻击；不可操作或无真实信息的页面未授权；无实际危害的未授权（如 swagger 已隐藏 api 信息）；同域名同系统 = 1 个漏洞；SSL/TLS 证书与安全设置类；登录/注销 CSRF；可自行注册用户的弱口令；无实际意义的扫描器报告；登入登出 URL 跳转；Self / DOM / POST 型及难利用的反射 XSS；批量注册；邮箱轰炸；无法证明存在或危害的结论；密码/账户策略类；点击劫持 / 缺安全报头 / 错误信息类；高德、百度等地图 API 泄露；正常业务逻辑；无高权利用的 PDF XSS；fastjson dnslog 有响应但无后续利用；其他危害不大项。

## 6. 定级细则

- **弱口令**：管理权限 = 高；普通权限 = 中低；可自注册 = 不收；同系统多用户弱口令只收第一个；非常规弱口令须说明来源；经其他漏洞取得的口令禁报弱口令。
- **SQL 注入**：默认高，但**须注出 ≤3 条数据证明危害，严禁拖库**；单纯报错被忽略。
- **未授权访问**：默认高（Web 页面 / ZK / Rsync / Redis / FTP 匿名 / 任意用户登录 / 登录绕过等），裁判可按页面价值降级；Druid 未授权 = 中；SMTP 未授权 = 中（须证明能发信）。
- **越权**：水平越权默认中（可升降）；垂直越权默认高。
- **XSS**：存储型实际拿到管理员有效 cookie = 高，否则中；文件上传型 = 低；反射型 = 低。
- **SSRF**：默认中；无回显须证明请求由服务端发起或可探测内网，否则不收。
- **文件类**：任意文件上传 / 读取 / 下载 / 包含、命令执行 / 反序列化各家族 = 高；仅 dnslog 探测不收，须外带数据或反弹 shell。
- **业务逻辑**：任意用户密码重置 = 高（须用新密码成功登录，仅「修改成功」截图退回）；短信验证码明文返回 = 高；短信内容篡改 = 高；短信验证码绕过 = 高；支付漏洞 = 高；短信轰炸 = 中（1 分钟同号 20 条 + 20 张截图）。
- **敏感个人信息定义**：**≥3 个敏感字段**（姓名 / 身份证 / 银行卡 / 手机号 / 邮箱 / 地址 / 金融交易记录），不足则降级。个人敏感信息泄露不单独收，注明数据类型与条数按加分规则计。
- **拿到 webshell 后禁止自行下载源码审计**，需风险申报授权，否则违规冻结。
- **撞库 / 爆破**：须有成功案例；后台爆破仅收成功登录者；利用难度高的按 CVSS 打分后降级。
- **源码泄露**：须证明与网站关联；边缘 / 废弃系统酌情降级。

## 7. CVSS 3.0 映射

| 等级 | CVSS 3.0 |
|---|---|
| 高 | 7.0 ~ 10.0 |
| 中 | 4.0 ~ 6.9 |
| 低 | 0.1 ~ 3.9 |

写报告时必须给出 vector 字符串与分数，且分数与影响描述对得上。

## 8. 证据硬要求（每类报告通用）

- 截图关键处**必须包含网络时间**。
- 不收疑似漏洞；证明不了危害的结论不写。
- 信息泄露类：≥3 条非自身数据。
- 暴力攻击类：≥10 次测试记录 + 最后一次成功结果。
- SQL 注入：≤3 条示例数据。
- 逻辑类：完整操作过程 + 利用后效果。

## 9. 执行规则

1. 定级与「是否值得报」以本文为准；格式按报告技能模板。
2. 每个漏洞落库 / 通报前，先过第 5 节不收清单与第 6 节定级细则。
3. 本文与报告技能冲突时，以本文为准（甲方裁判口径）。
