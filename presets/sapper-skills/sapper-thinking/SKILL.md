# 思考工具：发散备选与盲区分析

> 两件事：动手前先想够几条路（发散），收尾前先查漏没漏面（盲区）。两个都不许跳过。

## 一、发散备选方案

# 发散备选方案

你的任务**不是**定一个计划，而是基于图中已确认的事实，**生成多条互不重叠的可行路线**。数量与多样性优先于正确性——取舍交给指挥官。

### 82输入

先 `sapper_board` 看全局，再 `sapper_board(detail="facts")` 看已确认事实，必要时 `sapper_doc` 读关键节点的证据。

### 178要求

1. 每条路线独立成立：有自己的入口事实、技术路径、预期产出。
2. 互不重叠：不要给出同一技术的三个变体，那是同一条路线。
3. 数量 3–6 条，覆盖不同成本档位（10 分钟能出结果的 / 需要一小时的 / 需要长链的）。
4. 每条都注明：**依赖哪些事实 id**、**预期产出什么类型的事实**、**主要风险或失败模式**。
5. 优先复用图中已有的 `cred` 与已验证的 `vuln`——复用边际成本最低。

### 398输出

不要直接建意图。把候选写成一条 note 事实，供指挥官决策：

```
sapper_fact(
  description="基于 <事实摘要> 发散出 N 条备选路线",
  title="备选方案：<目标或资产短名>",
  kind="note",
  doc="## 路线 1：<短名>\n依赖：f001,f003\n打法：<一两句>\n产出：<fact 类型>\n风险：<一句话>\n\n## 路线 2：…"
)
```

然后给指挥官一句话建议（哪条先打、为什么），不要自己认领执行。

### 657纪律

- 不自作主张开工。
- 不重复图中已有的意图——先 `sapper_frontier` 看已经排了什么。
- 每条路线必须可在授权范围内完成，越界路线不写。

## 二、盲区分析

# 盲区分析

你的任务**不是**提出新工作，而是找出团队可能**没看见**的东西。输出是"哪里可能漏了"，不是"下一步做什么"。

### 69检查清单

逐项对照事实图：

1. **资产覆盖**：已发现的每个 host/service 是否都有状态（已测 / 已排除 / 待测）？有没有发现了却从没碰过的资产？
2. **假设未验证**：图里有没有"疑似"、"可能"、"待确认"这类措辞被当成了结论？
3. **线索断头**：有没有 fact 提到某个入口、凭据、路径，但没有对应的后续意图？
4. **证据缺口**：声称成立的漏洞，doc 里是否都有可复现命令与原始响应？哪些只有转述？
5. **定级可疑**：把影响描述与 CVSS 向量对一遍，有没有低危被报成高危、或"可能可以"被写成"确认"？
6. **范围漂移**：有没有动作触到了授权边界附近，却没有任何说明？
7. **重复与遗漏**：同一缺陷是否被拆成多条？同一资产的同类缺陷是否漏合并？
8. **收尾事项**：落地文件、测试账号、后门、上传物是否已列入撤场清单？

### 471输出

写一条 note 事实，按严重度排序列出：

```
sapper_fact(
  description="盲区分析：<N> 项待补",
  title="盲区：<阶段或目标>",
  kind="note",
  doc="## 1. <问题>\n影响：<会造成什么后果>\n证据：<引用 fact id>\n缺口：<具体缺什么>\n\n## 2. …"
)
```

随后用 `sapper_intent` 把**必须补**的项登记成意图（依赖相应事实 id），其余作为建议留在 note 里。

### 730纪律

- 只基于图中已有信息判断，不猜不存在的东西。
- 每条盲区都要引用具体 fact/intent id，不接受"感觉不全"。
- 不重复已经有人提出的意图。
