# 报告：结构、定级、模板与提交口径

> ⛔ **铁律一：写报告 = 逐字套用本技能模板**，禁止自行编排格式。字段（定级依据表/复测状态/内嵌证据图/数据包自检/撤场申报）缺一即打回重写。
> ⛔ **铁律二：通报 → 定级 → 决策 → 取证，顺序不可倒置。** 任何交付动作（截图取证、建漏洞目录、写报告）之前，必须先：① 醒目格式向用户通报漏洞名称/类型/证据；② 主控亲自完成定级（实害闸三问 + 档位 + 天花板校验）并向用户呈现结论与依据；③ 报告决策成立。通报前就截图 = 违规返工，已产出的截图作废（移 `raw/`）。
> ⛔ **铁律三：无实权实害不写报告。** 没拿到实权（shell/会话/管理员/密钥实值）或实害（他人数据/破坏能力）的发现，中危低危都不写；有利用价值的先利用升级，升不到高危就不出用户可见报告，只在 `raw/` 留一行 + `sapper_fact`。
> ⛔ **铁律四：零交付漏洞不出总报告。** 收尾时若无高危及以上实锤，不产出总报告文件，用一段话向用户汇报测试面/各面判定/残留物清理即可。
> 交付阈值一律以 `sapper-scoring` 为准；本技能的模板与提交口径只管「怎么写」，不管「收不收」。

## 适用场景

- 每确认一个高危漏洞后立即产出**单漏洞报告**（双轨制，禁止攒到最后）。
- 演练收尾汇总产出**总报告**（ATT&CK 映射 + 攻击链时间线 + 检测盲区 + 修复建议 + 撤场清单）。
- 按平台口径交卷（网安 2026 / 1.24 类 KPI）时，按第十节的字段与证据铁律准备材料。
- 交付前执行目录自检与报告质量自检。

## 前置

1. 全链路证据已留痕落盘（见 `pentest-00-orchestration` 证据纪律），时间戳齐全。
2. 漏洞已满足定级前置：**复测确认 ≥2 次**（见判定）。
3. 交付目录 `reports/【目标】/` 已建立。
4. 已加载 `sapper-scoring`（定级口径），且凭据/签名/密钥类 high 已由 auditor 车道盲审。

## 方法

### 一、双轨制与输出纪律

- **单漏洞报告**：每个漏洞确认后立即产出（用户实时看进度），并建对应漏洞文件夹。
- **总报告**：演练结束汇总全部单漏洞报告。
- **低危（low）与信息级（info）一律不输出**：不写单漏洞报告、不进总报告漏洞摘要/详情/统计、不作为成果交付；仅在 `raw/` 侦察笔记留一行内部留档。
- 中危是否输出：默认不输出（见铁律三），客户明确按平台 KPI 计分时由指挥官裁决是否补出，一旦决定出就按第十节口径写全。

### 二、报告目录结构（强制规范）

```
reports/【目标】/
├── 总报告-<目标>.md            ← 顶层唯一交付入口
├── 攻击面快照.md               ← 总报告"攻击面识别"素材
├── 漏洞报告/                   ← 每漏洞一个子文件夹
│   ├── 01-<漏洞名称>/
│   │   ├── <漏洞名称>.md        ← 单漏洞报告（文件名=完整漏洞名称）
│   │   └── evidence/            ← 该漏洞专属证据
│   │       ├── 01-<请求>-<YYYYMMDD-HHMMSS>.png
│   │       ├── 02-<响应>-<YYYYMMDD-HHMMSS>.png
│   │       └── 03-<成果证明>-<YYYYMMDD-HHMMSS>.png
│   └── 02-<漏洞名称>/ ...      ← 序号=确认顺序
├── 专项报告/                   ← 过程性报告（recon-*.md / exploit-*.md）
└── raw/                        ← 原始数据/中间产物/脚本/JS 样本（按阶段分子目录 + README 映射）
```

**顶层白名单**：顶层只允许 3 个报告文件（总报告 / 攻击面快照 / 平台导出）+ 3 个子目录（漏洞报告 / 专项报告 / raw）。其余 json/txt/csv/py/html/png 一律进 `raw/<阶段>/`，禁止散落顶层、禁止在项目根另建证据目录——"报告 + 证据"必须同处一个自包含交付包。

**命名规则**：
- 漏洞文件夹：`<两位序号>-<漏洞名称>`（序号 = 确认顺序）。
- 漏洞报告文件名：`<完整漏洞名称>.md`，禁止叫"漏洞报告.md / 成果报告.md"。
- 标题格式「资产/组件 + 漏洞类型短语」，如 `portal(WordPress) 任意文件上传致命令执行`；平台提交时官方类型从《漏洞标准》闭集原样选。
- 证据文件：`<序号>-<描述>-<YYYYMMDD-HHMMSS>.png`（工具界面完整截图，含 URL 与状态码；截图不可用时保存完整请求/响应原文于 evidence 并在报告注明）。

**证据纪律**：漏洞专属证据归档到该漏洞的 `evidence/`；跨漏洞过程证据进 `raw/<阶段>/`；总报告只引用路径不内嵌大段原文；每份报告落盘后立即把非报告文件归位。

### 三、漏洞定级纪律（先复测 → 五维评估 → 一次性定级）

**① 复测确认（定级前置，不可跳过）**：同一漏洞至少独立复现 **2 次**（换参数 / 换上下文 / 换时间点重放），结果一致才算"确认"；复测不通过 → 标记"未复现（停止上报）"，不进定级流程。报告"复测状态"字段写明。

**② 五维评估（逐项记录到报告）**：

| 维度 | 评估内容 | 作用 |
|---|---|---|
| 1. CVSS 基础 | CVSS 3.1 向量（AV/AC/PR/UI/S/C/I/A） | 基准分 |
| 2. 可利用性实测 | 深度验证：有无回显 / 内网是否可达 / 防火墙限制 / 实际能否打穿 | **大幅降级因子**（盲、内网不可达、无数据可读 → 下调 1~2 级） |
| 3. 攻击链价值 | 通向拿数据 / RCE / 横向，还是死胡同 | 升级评级依据 |
| 4. 业务影响 | 泄露什么数据、影响什么系统、有无真实敏感信息 | 结合业务定级 |
| 5. 前置条件 | 是否需认证 / 特殊条件 / 高权限 | 降级因子 |

**关键原则：CVSS 是起点不是终点。** 未做深度验证前禁止直接按 CVSS 理论值定级（盲 SSRF 理论 8.1，实测内网不可达只能低危→按输出纪律直接不出报告）。

**③ 定级锚点**：

| 场景 | 定级 |
|---|---|
| SQLi / RCE / 未授权文件写入（已打穿或直通数据） | 高危~严重 |
| 未授权数据泄露（实测拿到真实敏感数据） | 高危 |
| SSRF：内网可达 / 有回显 / 元数据可读 | 高危~中危 |
| SSRF：盲 + 内网不可达 + 无回显 + 无数据 | 低危（不输出） |
| 用户名枚举 / 版本信息泄露 | 中危~低危 |
| CORS 反射 / 安全头缺失（无实际打穿） | 低危（不输出） |

**④ 一次性定级 + 调整纪律**：定级动作链 = 复测确认 → 五维评估 → 最终级别 → 落图 + 单漏洞报告（写明定级依据）→ 不再随意变更。不因外部质疑变更，除非出现**新的验证证据**；允许调整仅一次，且必须留痕：`原:高危(CVSS 8.1) → 现:低危，原因:深度验证发现内网防火墙 DROP/无回显`。

### 四、单漏洞报告必含字段

```
漏洞信息表：名称 / 类型 / 严重程度+CVSS 向量 / 漏洞URL / ATT&CK 映射 / 受影响资产 / 复测状态 / 证据文件清单
定级依据表：复测次数 + 五维评估结论 + 最终定级 + 调整记录
漏洞描述：一段话成因与影响面
复现步骤：步骤一（说明）+ 完整可复现请求原文；步骤二（说明）+ 响应关键片段 —— 每步独立代码块
响应证据：`![描述](evidence/xx.png)` 相对路径内嵌证据图 + 真实响应关键片段（无证据不算确认；禁止 📎 纯文字锚点）
危害分析：编号列表 1/2/3
修复建议：立即 / 高优先级 / 中优先级 / 低优先级 四档
```

复现步骤格式要求：请求原文可直接复制重放（含头与参数），响应片段保留关键判定字段；证据截图与文字片段一一对应。

### 五、红队总报告结构（固定九段）

```
1. 执行摘要      —— 管理层视角：达成什么、核心风险、3 条建议
2. 测试信息      —— 范围 / 时间 / 授权 / 团队 / 规则 ROE
3. ATT&CK 攻击链总览 —— 战术 → 技术映射表
4. 攻击路径叙述  —— 时间线：每步的技术、证据、影响
5. 关键发现与风险评级 —— 按业务影响（含漏洞摘要表：#/名称/严重程度/CVSS/状态）
6. 检测盲区分析  —— 哪些环节蓝队/EDR 没抓到
7. 修复建议      —— 按优先级（对应具体盲区）
8. 撤场与清理清单
9. 附录          —— IOC、工具清单、完整命令留痕、测试账号清单、测试局限性
```

另含：攻击面识别（系统入口总览表 + 关键 API 表）、攻击链 ASCII 图（每步标注所用漏洞编号，区分最大危害链与次要链）、安全加固建议四档（紧急 24h / 高 1 周 / 中 2 周 / 低 1 月）。

### 六、ATT&CK 映射表（核心交付物）

| 阶段 | ATT&CK 战术 | ATT&CK 技术 | 证据 |
|---|---|---|---|
| 初始访问 | Initial Access | T1190 Exploit Public-Facing Application | 外网 SQLi → shell |
| 执行 | Execution | T1059.001 PowerShell | 反弹 shell |
| 持久化 | Persistence | T1053.005 Scheduled Task | schtasks 创建 |
| 提权 | Privilege Escalation | T1134.002 Create Process with Token | PrintSpoofer |
| 凭据 | Credential Access | T1003.001 LSASS Memory | procdump+pypykatz |
| 发现 | Discovery | T1482 Domain Trust Discovery | nltest |
| 横向 | Lateral Movement | T1550.002 Pass the Hash | impacket-psexec |
| 收集 | Collection | T1005 Data from Local System | 定位敏感文件 |
| 外渗 | Exfiltration | T1041 Exfiltration Over C2 Channel | HTTPS 上传 |

每环节写清：技术（工具+命令+payload 类别）、证据（真实输出/截图/留痕文件）、**是否被检测**（EDR/蓝队是否告警）。

### 七、攻击路径时间线格式

按时间顺序写故事线，每步一行：
```
[时间] [主机] [战术/技术] 做了什么 → 拿到什么能力 → 证据文件
```
让甲方能"跟随攻击者视角"走完完整攻击链。

### 八、检测盲区分析（红队报告最有价值的部分）

- 逐项列出**哪些攻击步骤蓝队/EDR 没有检测到**（红队演练的核心价值是测防御）。
- 每个盲区给检测建议（对应日志/规则/工具）。例："Pass-the-Hash 未被检测 → 建议启用 4624 登录类型 3 审计 + 网络监控"。

### 九、撤场与清理清单（必须写）

```
- [ ] 删除后门账户 / 计划任务 / 服务 / webshell / SSH 密钥（逐项列出）
- [ ] 恢复被修改的配置
- [ ] 销毁收集的数据 / 外渗产物（或按约定交还甲方）
- [ ] 关闭 C2 通道 / 隧道
- [ ] 时间窗内完成，超时立即停止并通报
```

## 十、平台提交口径（网安 2026 / 1.24 类）

> 只在本技能铁律三允许出报告、且甲方按平台计分时使用；与 `sapper-scoring` 的定级冲突时以 `sapper-scoring` 为准。

### 10.1 报告单元与命名
- 一漏洞一报告（禁止把多个漏洞糊成一份），每条漏洞独立 md，文件名 = 报告标题。
- 目录：`reports/<NN>-<官方类型>-<短id>/<报告标题>.md`，证据图放 `evidence/`，正文一律 `![描述](evidence/xx.png)` 相对路径内嵌显示，禁止 📎 纯文字锚点。

### 10.2 计分标注（1.24 普通漏洞上报口径）
- 严重 20：RCE/命令执行/反序列化 RCE/可 GetShell 上传/SQL 注入(有 DBA)/SSRF 打内网/任意文件读敏感配置/直接主机权限
- 高危 10：SQL 注入(无 DBA)/任意文件读取/非预期上传可解析/SSRF 有回显/存储 XSS 打管理员/越权看大量数据/未授权敏感接口/XXE 有回显/弱口令/逻辑缺陷可越权
- 中危 5：反射 XSS/CSRF 敏感操作/越权少量数据/未授权非敏感接口/目录遍历/配置文件泄露/API 敏感泄露
- 低危 1：信息泄露/CRLF/弱配置/自签名/点击劫持 —— **低危不上报**（api 文档、版本信息不收，只在侦察笔记留一行）

### 10.3 证据截图铁律（每张浏览器图）
1. 每张截图必须「地址栏 + 完整页面」同框——地址栏是访问该 URL 的唯一直观证明；视口截图（CDP shot）禁止作证据。
2. 平台工具：pwsh 有头浏览器截全窗 —— 用 pwsh 后台 job 启动有头 Edge/Chrome，再用 `System.Drawing CopyFromScreen` 截屏（含地址栏与完整页面），保存到 `evidence/<主名>_NN.png`；截完回看图片确认 URL 可读。
3. 发包证据四件套：填包帧 `_a.png` + 响应帧 `.png` + 请求原文 + 响应原文（md 内嵌）——用 pwsh 后台 job 起发包工具重放请求，再用 pwsh 截屏保存两张帧图；无 GUI 通道时以完整 HTTP 原文 + curl 回显替代并在报告注明。
4. **Yakit 三图必配**（数据包类成果，中危及以上）：
   - ① 分组图：HISTORY/MITM 中把本漏洞**全部请求拉进同一分组**后整窗截图（分组名与包列表必须入图）
   - ② Fuzzer 发包图：请求区与响应回显**同框**
   - ③ 复现关键包图：与正文内嵌数据包**一一对应**
5. 中危及以上交卷至少配其一；无图成果按模板「无图或不完善必忽略」。

### 10.4 完整数据包三铁律（复制即用）
1. http 代码块围栏与块内每行**顶格零空白**（缩进会被带进重放工具致 WAF 判畸形）。
2. 请求体与响应状态行之间**必须空行**；GET 无体则双空行。
3. 每个利用/验证请求独立完整包：请求行 + 全部请求头 + 空行 + 请求体 + 空行 + 状态行 + 全部响应头 + 完整响应体；对照组与利用组都给全，禁止箭头省略。
- 时间盲注等时序类标注实测耗时（基线 vs 注入）；认证类给「取凭证 → 登录 → 带凭证访问」完整闭环。

### 10.5 平台提交字段速记
攻击目标（授权清单内）/ 攻击时间段（与录屏对齐）/ 攻击方式（官方枚举多选：XSS、SQL 注入、弱口令、任意文件读取/下载、逻辑缺陷、非预期文件上传、XXE、SSRF、RCE、命令执行、配置文件泄露、未授权访问等）/ 成果标题 / 首页截图 / 漏洞地址 / 成果简要描述（手法+目标属性+危害）/ 复现步骤（配图）/ 修复建议 / 攻击残留（瞒报扣分：webshell、新增账号、上传文件全列）。

### 10.6 禁止项
- 拆洞重复提交、同系统同类型多次、把明确属其他类型的成果塞进 1.24；
- 报告出现本地绝对路径（外发纪律）；
- 用「可能/疑似/或许」措辞——只写实证判据。

## 十一、模板库与交付输出

| 文件 | 何时用 |
|---|---|
| `单漏洞报告模板.md` | **每个高危及以上（有实权/实害实锤）漏洞确认后立即一份** |
| `总报告模板.md` | 演练收尾一份，放 `reports/【目标】/` 顶层 |
| `report-nxist-nxbys-cn.md` | 格式参考样例（非模板，写完可对照检查） |

1. 写单漏洞报告：先加载 `sapper-scoring` → 过定级前置闸（凭据/签名/密钥类 high 须 auditor 盲审）→ read `单漏洞报告模板.md` → 逐字段填充 → 数据包排版自检 → PASS 才交付。
2. 写总报告：read `总报告模板.md` → 由各单漏洞报告汇总 → 按模板章节逐项过（零交付漏洞则不产出，见铁律四）。
3. **md 即最终交付（默认纪律）**：证据截图一律 `![描述](evidence/xxx.png)` 相对路径**独立成行内嵌**，交付前本地打开 md 确认全部图片能显示；`scripts/md2docx.py` 仅甲方明确索要 Word 版时才临时跑一次（docx 为临时派生物，以 md 为准）。修订只改 md；禁止直接编辑 docx。
4. 模板是独立 md 文件（非内嵌），直接编辑本目录文件即可更新，对所有会话即时生效。

## 判定

- 交付前**目录自检**：顶层只含白名单文件；散落文件归位（漏洞专属 → 对应 `evidence/`，过程产物 → `raw/`）；无项目根残留证据目录；`raw/README` 存在；本地打开报告 md **全部内嵌图片能显示**（相对路径有效）；grep 报告正文无失效证据路径引用、无 📎 纯文字锚点残留。
- **质量自检**：每条攻击步骤有 ATT&CK 映射 + 证据；时间线完整可回溯；检测盲区分析到位；修复建议可落地且对应盲区；撤场清单完整无残留；敏感数据脱敏、凭据不落报告。
- 进度可视化：每产出一个单漏洞报告给小结 `[漏洞 N/M 已确认]`。

## 证据

- 证据编号统一 `NN-描述-时间戳` 递增；单漏洞报告的"响应证据"章节只贴关键片段，证据图一律以内嵌 `![]()` 呈现。
- 攻击链每步证据文件路径写入时间线，报告只引用不复制大段原文。
- 事实图与报告双写（漏洞、资产分别记 `sapper_fact`），保持与报告编号一致。

## 升级

- 发现定级有误 → 仅一次调整机会，留痕"原级别 → 现级别 + 原因"。
- 复测不通过 → 停止上报，转 `raw/` 留档。
- 演练复盘：把检测盲区反馈给蓝队侧整改建议；把攻击面快照沉淀为下次侦察基线。

## 红线

- **低危/信息级不输出**是硬纪律：不因凑数放宽；此类只在 `raw/` 留一行。
- 无证据不算确认；证据必须真实（禁止伪造截图 / 拼接 / 复用他人截图 / 把工具输出伪装成线上页面）。
- 报告中凭据、身份证号、真实客户数据一律脱敏；凭据只出现去敏形式。
- 撤场清单未完成不得交付；超时间窗立即停止并通报。
